# Temporary render retention

New `studio prepare` packs explicitly register their generated portrait/wide PNGs.
`python -m studio.cleanup` reports eligible files without deleting anything.
`python -m studio.cleanup --apply` removes only those registered local PNGs once
all four exact approved platform posts have durable `published` receipts,
verified account/content/image, valid public URLs, and publication timestamps.
It waits 72 hours after the latest publication or verification, whichever is later.

Missing dates, queued/failed/unknown posts, changed assets, altered approval,
symlinks, hard-linked files, and legacy packs without an inventory are skipped.
Receipts and manifests remain for duplicate prevention. Original PDFs, reference
photos, captions, Drive originals and tracked repository media are not deleted.
Cleanup does not remove posts from social networks. Cleaned topics are not
automatically regenerated by prepare.

## Automatic operation

Run the cleanup command daily on the same persistent machine/storage that owns
`studio-output` and `studio-private/delivery.sqlite3`, using Task Scheduler on
Windows or cron on Linux. Set its working directory to the repository root and
use that installation's Python executable. Do not run it concurrently with
preparation/publication or while editing manifests. Dry-run once before enabling
`--apply`. A daily run means removal occurs on the first run after the 72-hour
threshold, not necessarily exactly at hour 72. Missed runs wait for the machine.

The repository's hosted GitHub Actions runner has neither this persistent local
journal nor local files. Therefore no misleading cloud cleanup job is installed.
Its draft artifacts retain their separate seven-day expiry. This change does not
install a task on the user's PC. Live automatic activation requires that runtime.

`scripts/install-cleanup-task.ps1 -PythonExe <absolute-python.exe-path>` is an
optional Windows installer for the publication machine. It requires an existing
journal, runs a dry-run, refuses to overwrite an existing task, and registers a
limited-permission daily noon task for the logged-in Windows user. It has not been
executed or Windows-tested in the development environment. It does not wake a
powered-off PC. Do not install until publication/storage paths are finalized.

Drive import deliberately remains read-only. Drive trash/retention automation
needs a separate explicit file inventory, verified receipts and authorized write
access; it is not silently enabled by local cleanup.
